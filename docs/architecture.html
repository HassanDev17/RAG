Reference architecture

RAG Chat

How one submitted question travels from the Streamlit browser session, through FastAPI's routing and service layers, to the active LLM provider and back — including the env-driven switch between providers.

Component notes

frontend/app.py
Streamlit chat UI. Holds message history in session_state, posts each prompt to the backend, renders the reply as markdown.
app/main.py
FastAPI entry point. Builds the app, configures logging, registers the exception handler, mounts the v1 router.
app/api/v1/chat.py
The POST /chat route. Parses the request body into ChatMessage, delegates to the service layer.
app/services/chat.py
handle_chat() — the one place business logic for a chat turn lives, independent of HTTP or provider concerns.
app/services/llm.py
generate_reply() and the cached get_llm() factory. Looks up the active provider class by name and normalizes its reply through response.text.
.env
Gitignored. Supplies LLM_PROVIDER, LLM_MODEL, LLM_API_KEY — nothing in the codebase names a vendor directly.

Provider swap

Every setting and function above is vendor-neutral by design — llm_provider, llm_model, llm_api_key, generate_reply(). Switching from Gemini to Anthropic (or adding a third provider) means changing LLM_PROVIDER and LLM_MODEL in .env and, for a new vendor, adding one entry to the _PROVIDERS dictionary in llm.py — no route, schema, or frontend code changes.
